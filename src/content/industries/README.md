# Industries

One YAML file per industry page. Phase C writes the nine entries; until the first one exists the `industries` collection is empty and the build logs nothing.

- **File name = entry id = nav slug.** `financial-services.yaml` holds the content for `/industries/financial-services/`. Name, path and one-liner live in `src/data/nav.ts` only.
- **Schema:** `makeIndustrySchema` in `src/content/schemas.ts`: exactly four workflow stages, at least three flagship use cases, five to seven FAQs, a `rulesThatTravel` paragraph, and (spec §8.5 blocks 2 and 5) 4–6 obligation chips, 3–5 `worksAlongside` systems and 3–4 recommended `packages`.
- **Page order (go-global §5.1):** the hero; "Rules that travel" (`rulesThatTravel`, then the chips from `src/data/anchors/`); the problem; how the work flows; packages; the scenario and first engagement; the Australia band (`#australia`), which holds the obligation chips ("Designed around"), the regulatory map or Government's jurisdiction sections, and the Australia-only FAQs (`#faq-au`); related insights; the FAQ; then the contact block. A page runs 900–1,800 words (Government 1,800–3,000), counting tables and the FAQ.
- **`rulesThatTravel`** is one paragraph of 140 words or fewer, ending with the page's travel sentence where it has one (go-global §5.5). It sits immediately before `problem:`. With its chips and closing line the block stays at or under 280 words (`tests/industries-global.test.mjs`).
- **Outside the band, copy reads for any country.** In the problem, workflow, package and scenario copy, an Australian statistic opens with "In Australia,", or with its state when it covers only one ("In Victoria, Australia,"). An Australian body or instrument is named in a parenthesis, as in "ISAE 3000 (ASAE 3000 in Australia)", or it moves into the band. An Australia-only package shows its "Australia" label.
- **FAQs:** an FAQ that is only about an Australian rule carries `region: au` and renders in the band's `#faq-au`; the rest render in `#faq`, and at least one stays untagged. The page's one FAQPage carries every FAQ in file order, so a tagged FAQ's wording is held to the same identity rules as the rest of the page (`tests/global-identity.test.mjs`).
- **Government (`jurisdictions`):** an industry that lists `jurisdictions` meets those counts in each sub-section it covers (Commonwealth: `cth`; State: `nsw`, `vic`, `qld`; Local: `local`), and every chip, system and package names its `jurisdiction`. Without `jurisdictions`, none may. The sub-sections sit inside the Australia band.
- **References by id:** `leadSolutions` and every use case's `solution` are solution ids (`src/content/solutions/`); each package names a solution id and one of that solution's package ids (its generic package or a launch or on-request package, never an internal one); each obligation chip's `row` is a row id in `src/data/regulatory/<industry-id>.json`, and a chip's `jurisdiction` is one that row lists; `scenario.trace` is a trace id in `src/data/traces/`. CI check 1 fails on an id that doesn't resolve.
- Only `*.yaml` files are loaded; this README is ignored.
