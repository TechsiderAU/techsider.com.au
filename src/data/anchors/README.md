# Anchors

The "Rules that travel" block on each industry page (go-global spec §5.2, §5.3): the international and cross-border rules, standards and guidance a page maps its evidence to. One JSON file per industry, named by its industry id (`manufacturing.json`), plus `shared.json` for the anchors any page can show. Each file is shaped `{ "shared": [ … ], "anchors": [ … ] }` and validated by `anchorFile` in `src/content/schemas.ts`, as the `anchors` collection. Routes read the collection with `getCollection("anchors")`, never `getEntry`, which logs a build warning for a missing file. The industry route fails the build ("… src/data/anchors/shared.json does not exist") when `shared.json` or a shown industry's file is missing.

- Every anchor has `id`, `name`, `issuer`, `kind`, `binding`, `status`, `asks`, `evidence`, `source`, `asAt`, `lastReviewed`, `solutions`, `featured` and `checkLevel`, plus `statusDate` and `reviewBy` where the rules below need them.
- `kind` is `law`, `treaty`, `international-standard`, `supervisory-principles`, `guidance` or `professional-ethics`. A chip prints it as Law (law, treaty), Standard (international-standard, professional-ethics) or Guidance (supervisory-principles, guidance).
- `status` is `in-force`, `applies-from`, `published`, `draft` or `not-in-force`. `applies-from` and `published` need `statusDate`, which the chip prints ("applies from 2 Dec 2027", "published Sep 2026"). An `applies-from` chip prints the day, so its date is a full `YYYY-MM-DD`; a `published` chip prints only the month, so a date the source gives only to the month may be written `YYYY-MM`. A date known only to the year (`YYYY`) would print as January, so it stays on an anchor that isn't featured. `asAt` is the chip's "as at" month.
- `binding` is one plain line in the source's own terms. `asks` paraphrases what the source asks: quote a paywalled standard briefly at most, and link its official listing. `evidence` names an artefact we produce. Neither ever claims conformity with the anchor.
- `source` is the primary source's URL, and the chip links to it. `solutions` lists solution ids.
- Ids: `shared.json` uses the research ids `x1` to `x8`. A sector anchor's id is a kebab slug that names the instrument or provision (`bcbs-operational-resilience`, `eu-ai-act-annex-iii-5b`), never `x` and a number. An id appears once per page, across the shared row and the industry's own anchors; the same id may recur in another industry's file when it names the same instrument.
- The shared row: each industry file's `shared` array lists, in order, the four or five `shared.json` ids its "Everywhere" row shows: `x1`, `x4`, `x6` and `x7`, with `x8` last on accounting, manufacturing and real estate. Each id it lists is featured in `shared.json`, which has no `shared` key of its own.
- Each industry file features two or three of its own anchors, and none of their ids is in its `shared` row. `industryView()` in `src/lib/views/industry.ts` fails the build on a `shared` id that `shared.json` doesn't feature, on more than three featured sector anchors, or on a sector id that repeats a shared one, and `tests/anchors-content.test.mjs` pins each page's shared row, featured set and chip text. With its paragraph and closing line, the block stays at or under 280 words.
- `featured: true` renders an anchor: in an industry file, as one of the page's two or three sector chips; in `shared.json`, as an anchor a `shared` row may list. Only `checkLevel` `P` (primary source read) or `P*` (primary source blocked, facts corroborated) may be featured. An `S` anchor (secondary sources only) stays `featured: false` until a person reads the primary; that read moves its `checkLevel` to `P`, and its `asAt` and `lastReviewed` to the day of the read. No `UNVERIFIED` anchor is written here, and no field or claim that a research Verification table marks UNVERIFIED or UNVERIFIABLE, or that spec §5.3 holds back, such as the IMDRF N88 date.
- `reviewBy` is required when `status` is `applies-from`, `draft` or `not-in-force`, and on every anchor whose name cites the EU AI Act or GDPR. CI check 13 warns from 30 days before the date and fails the build once it has passed: review the anchor, then move the date. Review every anchor at least once a quarter.
- Only `*.json` files are loaded; this README is ignored.
